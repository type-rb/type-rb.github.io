Migrate to Result control flow in TypeRB 0.3

TypeRB 0.3 uses one recoverable-error representation: Result<T, E>. It removes the fails E function effect and the attempt expression, and adds prefix try for compatible propagation and postfix catch for local recovery.

This is a source-breaking migration. Update package contracts and their callers together, then run trb fmt and trb check --diagnostic-format json before executing the target application.

Return Result from recoverable operations

Change a fallible return contract from a success type plus fails E to an ordinary Result return:

# TypeRB 0.2
def load_user(id: Integer): User fails LoadError
	return repository.find(id)
end

# TypeRB 0.3
import { Result } from trb/std/result

def load_user(id: Integer): Result<User, LoadError>
	return repository.find(id)
end

Every authored success path must now construct or return Ok. Operations with no application success value use Result<Unit, E> and return Ok(Unit.new()).

Function values use the same ordinary return type:

loader: () -> Result<User, LoadError> := fn(): Result<User, LoadError>
	return load_user(42)
end

Replace automatic propagation with try

Use prefix try only in a function returning a compatible Result:

def load_profile(id: Integer): Result<Profile, LoadError>
	user := try load_user(id)
	profile := try load_user_profile(user)
	return Result<Profile, LoadError>::Ok(profile)
end

try unwraps Ok and returns a new Err from the nearest compatible Result boundary. It does not convert unrelated error types implicitly. Use catch and construct the outer error when a boundary changes the error type.

Replace local capture with direct Result handling

An operation that used to require attempt already returns a Result in 0.3. Keep it intact for later inspection:

result := load_user(42)

case result
when Result::Ok(user)
	puts(user.name)
when Result::Err(error)
	puts(error.message)
end

Use postfix catch when only the success value should continue:

user := load_user(42) catch |error|
	puts(error.message)
	return
end

puts(user.name)

The handler must produce the same success type or transfer control with a valid return, break, or next. catch handles only Result::Err; it does not intercept native exceptions, Promise rejections, or panics.

An old attempt do ... end block has no mechanical one-line replacement. Move the sequence into a named Result-returning function, use try at each propagation point, and call that function normally. This preserves the exact error type and return boundary instead of introducing an implicit block effect.

Handle every Result

The compiler-owned standard Result is required-use in 0.3. A bare Result expression and an unread Result local are errors, including a local named _result. Handle it with try, catch, exhaustive case, or return, or pass or store it as data. The check is shallow and does not recursively inspect containers.

The REPL top level displays Ok or Err and is exempt from required-use. Top-level try remains invalid so an interactive error cannot leave an implicit propagation boundary.

Update official package boundaries

TypeRB 0.3 bundles the following package contract versions. Package versions follow their own pre-1.0 SemVer rather than mirroring the compiler version:

Package Bundled version
trb/orm 0.2.0
trb/jobs 0.2.0
trb/jobs/sql 0.2.0
trb/platform/typescript/browser 0.2.0

Other bundled packages keep their existing version when their source contract did not change.

  • trb/orm database terminals, lazy association access, explicit association load/reload, transactions, and batch streaming return DbResult<T>. Use try inside a compatible repository function and catch at an HTTP, Job, CLI, or other application boundary.
  • trb/jobs enqueue methods return Result<JobReference, EnqueueError> directly. A Job that asks the worker to retry returns JobResult, which is Result<Unit, JobError>; an infallible perform still omits its return type.
  • trb/platform/typescript/browser request, JSON/body contract, and File read operations return Result directly. TypeRB source still omits async; the backend retains the target suspension boundary.

Structured Result operations such as Database.transaction(), find_each(), and find_in_batches() complete rollback or cleanup before an outer catch runs. Their direct try or catch wrapper must remain the direct value of a variable declaration or return.

Upgrade native TypeScript providers

Native provider and generated cache format version 2 removes the fails and effectBridge fields. A Promise callback that accepts a Result-returning TypeRB function uses resultBridge instead. Change the provider's formatVersion to 2, then run trb install to regenerate .trb/native-types.json.

TypeRB 0.3 rejects version 1 providers and caches with a migration diagnostic instead of interpreting their callback contract.

Keep case/when unchanged

TypeRB 0.3 does not add case/in or match. case/when continues to cover ordinary value branches, enum variant dispatch, and the current positional payload binding. try and catch remove routine Result branching, while an exhaustive case remains appropriate when both outcomes are data to inspect or when a payload enum has several meaningful variants.

Validate the complete boundary

After migrating one coherent dependency slice:

trb fmt
trb check --diagnostic-format json
trb test

Then run or build every configured target used by the application. In particular, exercise transaction rollback, Job retry, browser callback rejection, and any Result-returning function value; these are boundary behaviors that a source-only check cannot fully validate.
